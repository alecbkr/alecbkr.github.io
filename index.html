PRISM - SHADER SANDBOX

OVERVIEW

A GLSL shader development environment built from scratch using a custom OpenGL-based engine.

Prism provides a user-friendly 3D workflow by abstracting low-level rendering and resource management while preserving direct access to OpenGL's programmable pipeline. It integrates a real-time 3D viewport, code editor, console, and asset management tools into a unified workflow.

MY ROLE

I was Prism's 3D rendering system architect, which entailed designing a flexible rendering pipeline capable of drawing a wide variety of 3D model types to the viewport. Because Prism is meant to expose GPU control to the user, I had to consider several use cases in my design, including checking model and shader states, establishing rendering rules and ordering, and providing forward-facing support for changing model properties on the fly.


Rendering 3D models requires a series of organized steps, so my renderer relies on retrieving specific model resources at the appropriate time. I designed an object-oriented hierarchy of data structures that decomposes 3D models into subcomponents, storing GPU resources separately by type (models, meshes, materials, and textures). I built resource management systems for each type to handle storage, retrieval, and provide an interface for accessing GPU functionality.


Additionally, I introduced foundational framework tools that helped evolve Prism from a program into an application. I created a logger to record and print runtime errors and information, a dedicated application timer, and an initial input management class to relay keyboard and mouse inputs throughout the application.

REFLECTION

This was my graduating senior project and by far the most ambitious project I've ever worked on (and maybe a bit more than any of the team bargained for). It was an experience full of long nights, debugging, refactors, redesigns, etc, etc. But more importantly, it made me learn more and grow in ways that no amount of rubricked programming assignments could ever.


Huge thanks to the rest of the Prism team and our project manager Carsdan Dvorachek for this amazing opportunity.

SIMPLETON CHESS

OVERVIEW

A lightweight console chess game that demonstrates efficient game-state management and move validation in a text-based environment.

Simpleton Chess draws an ASCII game board, enforces the rules of chess through legal move checking, and improves player interaction with visual indicators that highlight every valid move available to the selected piece.

MY ROLE

Simpleton Chess was a personal project aimed at exercising my ability to independently engineer a game I know well. The focus was on translating the rules of Chess into data structures, states, and algorithms that work in tandem to mirror the real deal.


I engineered a modular gameplay loop that separates application and game responsibilities, allowing additional games to be integrated without modifying core application logic.


I designed a modular game board using a multidirectional linked-list structure, enabling O(n) traversal across tiles. Each tile maintains pointers to neighboring tiles and an occupant reference for the piece residing on it.


I developed algorithms to calculate and record all legal moves available to selected pieces, enforcing game rules and simplifying game-state validation.
